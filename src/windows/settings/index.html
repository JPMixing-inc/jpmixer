Setting up JPMixer

Work down the list. Each step opens the right place; the optional ones only matter if you use them.

Names fill themselves in.

Once your console is connected, JPMixer reads its channel names, mix names, and control groups (DCAs on dLive and LV1) straight from the console, so there’s nothing to type in. When the console changes a name, JPMixer follows, and it remembers the names, so they’re still here while the console is off. (KLANG and WING send channel names only, so name their mixes on the Aux mixes tab.)

Want a different name? Type your own on the or tab. It overrides the console’s name in JPMixer only (the console isn’t changed), and clearing it goes back to the console’s name. Control group and DCA names always come from the console.

    ⚠️ KLANG support is brand new and hasn't been validated on real hardware yet. Channel gain, mute, solo, and stereo-mode pan work; 3D/i3D positioning, built-in EQ, and the Console Controller are not implemented.
    How KLANG reports mix changes
    KLANG has no way to confirm back what value it actually applied — JPMixer trusts its own last-sent value as the mix state. If someone also has the real KLANG:app open adjusting the same mix, JPMixer won't notice the difference.
    Pairing KLANG with dLive
    The dLive console fields below are optional in this mode — set them to pull channel names and drive Ear Scene recall from the paired console's own snapshot changes. Leave the Console IP Address blank to skip that and control channel names manually on the Channels tab instead.
    ⚠️ WING support is brand new and hasn't been validated on real hardware yet. Aux send levels, mute, solo, and per-send pan work; built-in EQ, Console Controller, and Ear Scene / snapshot recall are not implemented — WING's OSC layer doesn't expose scene recall at all.
    Leave at 0 to use the documented default OSC port. WING confirms it's actually reachable with a real round trip on connect, unlike dLive/KLANG — the Console status pill above reflects that directly.
    ⚠️ LV1 support is brand new and has only been tested against an LV1 show, not yet during a live service. Aux send levels, mute, solo, per-send pan, live channel and mix names, Ear Scenes (by LV1 scene name) and the Console Controller (channel, aux and DCA faders, mutes and solos) work; its ‹ › scene buttons haven’t been confirmed on a real LV1 yet, and built-in EQ and the channel processing panel are not implemented.
    Switch on LV1’s MyMon remote
    JPMixer connects the same way Waves’ MyMon and MyFOH apps do. In LV1, switch on the MyMon / MyFOH remote. JPMixer then finds LV1 on the network by itself, the way the MyMon app does, and reads channel and mix names and counts from the LV1 show. Leave LV1 Computer IP Address blank to use the LV1 it finds (this computer’s first). Enter the LV1 computer’s address when it’s on a different network from this one (LV1’s announcements don’t cross routers; JPMixer then finds LV1 by checking that computer directly, which can take up to half a minute after LV1 starts), or when more than one LV1 is on the network.
    LV1 picks a new port each time it starts and announces it on the network. Leave this at 0.
    ⚠️ dLive support has been tested against dLive Director running offline, not yet a real MixRack. Aux send levels, mute, solo, scene recall, Ear Scenes, live names, a mix’s EQ for its musicians, FX returns in the mixes, pan on the stereo mixes and the Console Controller (faders and mutes of channels, auxes, DCAs, FX, groups, matrices, mains and mute groups, and each channel’s preamp, high-pass and EQ) work. To try it without a console, run dLive Director offline with System → Offline → “Enable Director Connections to MixRack IP Controllers” ticked, and use this computer’s address with Director’s MIDI channel.
    Enable MIDI control on the dLive console
    On the console: Utility → Control → MIDI has its own On/Off/Secure Mode switch for MIDI/TCP — it must be turned on there before JPMixer (or anything else) can connect, the same way DiGiCo consoles need DiGiCo Pad enabled. Unlike DiGiCo Pad, though, dLive doesn't limit this to one connection at a time — JPMixer can run alongside Director, MixPad, and other control apps without conflict.
    Base MIDI Channel must match the value set on the console under Utility → Control → MIDI (0-11, i.e. MIDI channel 1-12). Find asks the console at the address above.
    How many of the console’s FX returns every mix has after the inputs, so a singer can have reverb in their ears (0-16). They’re named as on the console.
    Port troubleshooting
    Leave at 0 to use the documented default. If the console doesn't respond, try 51328 (the alternate port some tools use) — see JPMixer's dLive notes for why this isn't fully settled yet.
    Advanced send-level updates
    Trust the console's own unsolicited updates when a send changes. Should stay on — turn off only if you find it's producing wrong values.
    Actively re-requests each active mix's send levels in the background, in case live updates above aren't actually happening. Safe to leave on; turn off once you've confirmed live updates work to reduce console traffic.
    A musician’s mute switches the send off on the console and its level stays as it was. Off: the send goes to −∞ and its level is put back after, as on DiGiCo. Leave on unless the console doesn’t take it.
    dLive’s MIDI control has no pan for a send, so JPMixer pans the stereo mixes the way dLive’s own apps do (TCP port 51321). It finds each mix by itself and checks it against the levels MIDI reads; a mix that doesn’t check out has no pan. Turn off if a firmware update stops it working.

    Lists the receivers on this network and reads the ones you tick below.
    Try one receiver first, outside a service. JPMixer reads receivers through Shure’s control port (2202), the one Crestron and AMX use, and only ever asks; it never changes a receiver or turns on its meters. QLX-D firmware 2.2.11 and later was reported to freeze on that port while streaming meters over a shaky network, which JPMixer avoids.       Backup files

      Export a copy to keep, or restore an existing setup.

      Export Backup

      Save your console settings, channel/aux setup, My Mixes and Ear Scenes to a file. Useful before an app update, or to move everything to a new computer.

      The Planning Center App ID and Secret, dLive password and Control API token. Leave off for a backup you’ll share or keep somewhere others can open it. Restoring a backup without them keeps the ones on this Mac.

      Load & restore a backup

      One loader for JPMixer backups, My Mixes backups, and extracted JSON or ZIP files. Review the contents before anything changes.

      Choose what to restore. Unchecked sections and anything missing from the file stay as they are. Credentials are never selected automatically.

      Sections to restore

      Identical copies are skipped. Different mixes with the same name receive a numbered suffix.

      A safety backup is created first. Restoring saved mixes does not apply their levels to the console. Selected settings replace their saved values and reload Settings.

      External Control API

      Connect Companion, Stream Deck, or another HTTP tool to control mutes, snapshots, and channel or aux names. Planning Center is configured separately.

      Runs independently of the console connection — enabling or disabling this never restarts or interrupts it.
